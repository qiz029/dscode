# DSCODE 0.7.26

This release adds durable trigger scheduling and script event sources, fixes model-effort and provider-error presentation, and reorganizes the footer around API-backed TPS and right-aligned finances.

- **Trigger session modes (feature)**: an event can create a fresh session or resume a persistent session bound to the trigger id. Persistent events retain context while receiving independent goals and execution limits. Events serialize under the existing locks; missing bound sessions or workspace changes fail rather than silently discarding history.
- **Cron and delay jobs (feature)**: calendar, interval and polling sources enqueue durable SQLite jobs, and one-shot jobs support delay/absolute-time scheduling and cancellation. The shared scheduler tracks cursors, time zones, misfires, overlap and pending reasons. Failed runs are not automatically retried, and unattended approval requirements stop a run for review. Installing and starting the background scheduler remains explicit.
- **Agent and TUI management (feature)**: `trigger_manage`, `trigger_jobs`, `trigger_scheduler`, `trigger_source`, `/trigger` (alias `/triggers`) and the CLI share management state and workspace boundaries. The slash command runs without calling a model. Mutations retain approval checks; read-only/plan sessions, subagents and unattended runs cannot mutate schedules through these management tools.
- **Script event sources (feature)**: finite polling scripts and supervised daemon loops can emit events through a scoped local ingress into the durable queue. Event identity, retry acknowledgements, conflict detection, queue backpressure and lifecycle logs make loop integration inspectable. Filesystem sandboxes and guardian processes restrict sources and clean up ordinary descendant process groups. Unsupported sandbox environments fail closed; detached-process evasion and arbitrary external services are outside the automated guarantees.
- **DSCODE preset and effort selection (change/fix)**: the interactive preset stays fixed to DSCODE, with `/mode` hidden and other preset selections rejected. Legacy transcripts survive resume under DSCODE. Switching from MiMo `medium` to DeepSeek now opens its effort picker at the advertised default `high`; the footer no longer borrows an earlier model's effort. Supported selections are retained, and request-boundary validation remains in place.
- **Content-policy failures (fix)**: OpenRouter's untyped content-filter 403 is classified as `CONTENT_POLICY`, with an explanation that the turn stopped, instead of being mistaken for an authentication problem. Ordinary credential failures keep their classification. This improves live and replayed error presentation; it cannot bypass a provider's policy or automatically retry a rejected request.
- **API-backed smoothed TPS (change)**: completed main-agent requests contribute their reported output token count divided by measured full request duration, including first-token latency. Each valid request multiplies older sample weights by `0.5` before adding its own weight of one and normalizing. Idle time does not age the reading; aborted or missing-usage calls do not update it, and a new model/provider/effort request resets it. Byte-count estimates and the `~` prefix are removed. A separate request indicator animates without changing the number and respects the animation preference.
- **Grouped footer (change)**: TPS, average, context and skills remain on the left; cost, DeepSeek balance, peak/off-peak, last-turn cost and cache align together on the right. Narrow terminals move finances to a third row, and the live viewport and IME cursor account for its height. Very narrow layouts can omit average TPS or last-turn cost and finally clip oversized financial text; unavailable balance data remains unavailable.

Verification: `npm run check` passed locally, including 542 unit tests under coverage, both TUI type checks, lint, all isolated Harness integration probes, package integrity/exports checks, and 51 evaluation tests. The documentation checker also passed. Render cases cover 48, 60, 80 and 120 columns, stable numeric TPS during activity animation, and third-row viewport accounting. Deterministic fixtures cover provider errors, model switching, durable jobs, script ingress and trigger session modes without paid model requests. `npm run build:packages`, `npm run release:hub` and `npm run verify:hub` also passed: the candidate installed through the real Hub lifecycle, ran deterministic agent/shell/subagent, messaging, card and memory probes, and survived a failed upgrade, successful upgrade and rollback with state retained. This local check used a loopback registry, not public package discovery.

Not covered by those checks: human acceptance in a live terminal/IME, Linux script sandbox execution on this macOS workstation, real provider inference or moderation behavior, and a newly installed persistent scheduler on the user's machine. The release does not install or start such a scheduler.
