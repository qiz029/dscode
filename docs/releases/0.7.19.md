# DSCODE 0.7.19

This release stops an escalation the user already asked for from interrupting a human every time — the second model in automatic review decides it instead; and it fixes the chain that made an agent calling a CLI with its own credentials look "not signed in".

- **An authorised escalation goes to a deeper model review (change, automatic review)**: Jev has four guards on the allow direction — credential risk ≥ 0.5, hard to undo (`score ≥ 2`), a `choice` other than `allow`, and confidence < 0.85. They used to go to a human every time and **ignored whether the instructions had already authorised the action**: a build verification that has to leave the sandbox inside a "commit and release" task therefore prompted for approval every time. Now, as long as `authorized ≥ authorizedVeto`(0.6) — the retained instructions appear to ask for it — those four guards return `defer` instead, leaving it to the reviewer model that can see the full pending arguments and the instructions. Jev's scores are coarse by nature, and this deployment's policy already allows ordinary network access and lets a CLI use credentials it stored itself, so these guards should not veto on their own. **The deny direction is unchanged**: a decisive denial, and "the instructions appear to veto this denial", still work as before. A `defer` is never treated as an allow (`applyVerdict` only accepts an explicit `allow`), and a reviewer ruling of `human` still consults a human; one `defer` leaves two rows in the audit — Jev's verdict and risk scores, and the final ruling.
- **Hub login aligned to the state directory (new, launcher)**: `dsh-hub login` writes `$DSH_HOME/.hub/auth.json`, but a user who logged in outside DSCODE wrote `~/.dsh/.hub/auth.json`. When DSH_HOME points elsewhere, the CLI inside the agent reports "Not signed in" — and at release time that is exactly the chain that sends people off to "export a token", which is then judged a credential risk and routed to a human again. The launcher now copies that login into this session's `$DSH_HOME` (when the target does not exist): the directory is normalised to `0700` and the file to `0600`, an existing copy always wins (a fresh token the CLI refreshed is never overwritten by the old file), and any read/write failure is ignored silently — a convenience copy must never make the launch fail. The copy lands in the state directory, which also lets the CLI refresh its own session without leaving the sandbox.

Verification: `npm run check` passes (lint, coverage, integration, packaging and evaluation all green). New tests cover "the four guards return `defer` when authorized", "below `authorizedVeto` it is still `human`", "an authorised decisive denial still goes to a human", "a `defer` goes to the reviewer model and spends no human", "a reviewer ruling of `human` still finds the user", and for the credential alignment "no action without a login / copied once / an existing copy wins / a loose directory is tightened to 0700 / an unreadable source does not throw".
