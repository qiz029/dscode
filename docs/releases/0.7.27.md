# DSCODE 0.7.27

This patch release repairs fresh npm/Hub installation and adds the native dependency-lock path to release verification.

- **Fresh installation (fix)**: Harness composition creates an empty `cordis.yml` after Hub CLI 0.5.0 records installation inputs. The final receipt check previously rejected that generated file and discarded the staged profile. The launcher now carries a build-time vendored CLI that excludes only the exact generated file hash when no package-manager hooks are present. Custom root content, hook-bearing profiles, other configuration files and lockfiles remain checked. No recipient dependency files are patched at install time.
- **Release verification (fix)**: candidate verification now runs the native locked installer, starts the installed launcher with `--dump-config`, and checks Hub doctor. Publication requires those results against the exact package hashes. Existing external-executor agent, failed-upgrade and rollback probes remain, but no longer stand in for native installation.

Verification completed before tagging: `npm run check` passed (lint, both typechecks, 543 unit tests, 83.55% measured `.mjs` line coverage, isolated Harness integration probes, package checks and 51 evaluations); documentation links are clean. `npm run verify:hub` passed the native locked installation, launcher first start and Hub doctor, as well as installed-agent, failed-upgrade, replacement and rollback probes. The regression test accepts only the pinned generated root and rejects custom root content, package-manager hook cases, other input changes and lock changes. No paid provider request or human TUI interaction is part of this patch's installation proof.
