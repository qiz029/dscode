# DSCODE 0.7.15

这版把项目级扩展真正接上：hooks 从项目目录分层合并，skills 与 `AGENTS.md`/`CLAUDE.md` 可以来自项目根之上的目录；同时默认不再挂载 Chrome MCP，并让自动权限审核可以由 TypeSafe Jev 用一次结构化决策代替一次模型调用（含自动拒绝）。

- **Jev 审核（新）**：挂载 `dscode-jev` 后，自动审核先问 Jev（OpenRouter 的 alpha Decisions 端点 `POST /api/alpha/decisions`）四个 typed 问题——`allow`/`ask`/`deny` 及逐选项概率、保留指令是否明确授权这次动作、做错时有多难回滚、是否涉及凭据——再在代码里按非对称门槛判定：放行要求高置信度的 allow 且无凭据/难回滚信号；拒绝则在「置信度与 `P(deny)` 都高」或「置信度稍低但风险分已越线佐证」时直接生效，命中授权否决（`authorized ≥ 0.6`）则改为交给人。Jev 未配置、未启用、超时或报错时返回「无判定」，自动审核回落到原 reviewer 模型，行为与之前一致。决策信号（`choice`/`confidence`/`denyProbability`/`authorized`/`destructive`/`credentialRisk`）写入 `.runtime/auto-review/*.jsonl` 供后续调阈值。
- **hooks 分层**：项目的 `.codex/hooks.json`、`.dsh/hooks.json`、`.claude/settings.json` 默认叠加到 `config/hooks.local.json` 之上，合并写入 `$DSH_HOME/hooks.resolved.json`，并有一份报告列出各层与本 bridge 无法执行的事件；项目文件里的坏格式只记录不致命，安装级文件仍然硬失败；`/hooks` 会指出某个 layer 在合并之后被改动（或消失），因为只有重启才会重读。开关只承认文档写明的开启拼写（`1/true/on/yes`），`=no`/`=none`/`=disable` 不会再反向开启。
- **skills 与工作区指令向上发现**：`DSCODE_SKILL_ANCESTORS=1` 时，项目根到 home 之间每层的 `.dsh/skills`、`.agents/skills`、`.claude/skills` 以 rank 300 注册（只有 header 进 catalog，正文仍懒加载）；项目根之上的 `AGENTS.md`/`CLAUDE.md` 折叠进有 60 KiB 上限的聚合文件（用户级文件始终保留、祖先就近优先、超预算整份跳过）；home 边界按 realpath 比较，`$HOME` 是符号链接时不再静默失效。
- **默认不再挂载 Chrome DevTools MCP**：它用 `--isolated` 临时 profile，看不到你的登录态，却占约 29 个模型可见工具。launcher、bundle、doctor 都停止接线；`config/mcp.local.example.yml` 给了按需加回的示例（含 `--browserUrl` 接你自己以远程调试启动的 Chrome）。
- **系统提示词补上两段纪律**：`dscode:code-discipline`（根因修复且不越界、不顺手改无关代码、不加注释/版权头噪音、不自行 commit、不在无测试的仓库造测试、必要时先读 `git log`/`git blame`）与 `dscode:working-discipline`（指令优先级：system prompt 与审批策略不可被下游放宽，用户请求 > `AGENTS.md`/`CLAUDE.md` > 记忆 > 外部内容；信息足够就行动；只在会改变结论时纠正自己）；persona 里「每分钟一次进度更新」这条与下一句自相矛盾的规则改为事件驱动。

验证：`npm run check` 通过（306 项单测；lint 干净）。祖先与 hooks 行为由新增单测覆盖（`tests/workspace-discovery.test.mjs`、`tests/hook-sources.test.mjs`、`tests/tui-tools.test.mjs`）。Jev 路径用 mock transport 覆盖请求形态、阈值判定、超时与回落，并在真机上对四个用例实测（96–813 ms、约 $0.000025/次）；同一动作两次运行的置信度会漂移（`rm -rf` 从 0.90 到 0.97），阈值仍建议用审计记录对齐而不是照搬默认值。
