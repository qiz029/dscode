# DSCODE 0.7.15

This release really connects project-level extensions: hooks merge in layers from the project directory, skills and `AGENTS.md`/`CLAUDE.md` can come from directories above the project root; it also stops mounting Chrome MCP by default and lets TypeSafe Jev replace one model call in automatic permission review with one structured decision (including automatic denial).

- **Jev review (new)**: with `dscode-jev` mounted, automatic review first asks Jev (OpenRouter's alpha Decisions endpoint `POST /api/alpha/decisions`) four typed questions — `allow`/`ask`/`deny` with per-option probabilities, whether the retained instructions clearly authorise this action, how hard it is to roll back if it goes wrong, and whether credentials are involved — then decides in code against asymmetric thresholds: an allow requires a high-confidence allow with no credential or hard-to-undo signal; a denial takes effect when "confidence and `P(deny)` are both high" or "confidence is a little lower but the risk score corroborates and is over the line", and an authorisation veto (`authorized ≥ 0.6`) turns it into a hand-to-human. When Jev is unconfigured, disabled, times out or errors it returns "no verdict" and automatic review falls back to the original reviewer model, behaving as before. The decision signals (`choice`/`confidence`/`denyProbability`/`authorized`/`destructive`/`credentialRisk`) are written to `.runtime/auto-review/*.jsonl` for later threshold tuning.
- **Layered hooks**: a project's `.codex/hooks.json`, `.dsh/hooks.json` and `.claude/settings.json` stack on top of `config/hooks.local.json` by default and merge into `$DSH_HOME/hooks.resolved.json`, with a report listing each layer and the events this bridge cannot execute; a bad format in a project file is only recorded, never fatal, while an installation-level file still fails hard; `/hooks` points out a layer that changed (or vanished) after the merge, because only a restart re-reads it. The switch accepts only the documented spellings for on (`1/true/on/yes`), so `=no`/`=none`/`=disable` no longer turns it back on.
- **Upward discovery for skills and workspace instructions**: with `DSCODE_SKILL_ANCESTORS=1`, the `.dsh/skills`, `.agents/skills` and `.claude/skills` of every level between the project root and home register at rank 300 (only headers enter the catalog, bodies stay lazy); `AGENTS.md`/`CLAUDE.md` above the project root fold into a 60 KiB-capped aggregate file (the user-level file is always kept, the nearest ancestor wins, an over-budget source is skipped whole); the home boundary is compared by realpath, so it no longer silently fails when `$HOME` is a symlink.
- **Chrome DevTools MCP is no longer mounted by default**: it uses an isolated `--isolated` temporary profile, cannot see your login state, and occupies about 29 model-visible tools. The launcher, bundle and doctor stop wiring it; `config/mcp.local.example.yml` gives an example of adding it back on demand (including `--browserUrl` to reach a Chrome you started with remote debugging).
- **Two discipline sections added to the system prompt**: `dscode:code-discipline` (fix the root cause without overstepping, do not touch unrelated code, add no comment or copyright-header noise, do not commit on your own, do not invent a test suite in a repo that has none, read `git log`/`git blame` first when it would settle a question) and `dscode:working-discipline` (instruction precedence: the system prompt and the approval policy cannot be loosened downstream, user request > `AGENTS.md`/`CLAUDE.md` > memory > external content; act once there is enough information; correct yourself only when it would change a conclusion); the persona rule "a progress update every minute", which contradicted its own next sentence, became event-driven.

Verification: `npm run check` passes (306 unit tests; lint clean). The ancestor and hook behaviour is covered by new unit tests (`tests/workspace-discovery.test.mjs`, `tests/hook-sources.test.mjs`, `tests/tui-tools.test.mjs`). The Jev path uses a mock transport to cover the request shape, threshold judgement, timeout and fallback, and was measured on a real machine over four cases (96–813 ms, about $0.000025 each); the confidence drifts between two runs of the same action (`rm -rf` from 0.90 to 0.97), so thresholds should still be aligned with the audit records rather than copying the defaults.
