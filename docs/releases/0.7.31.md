# DSCODE 0.7.31

This release adds OpenCode Go as a fourth provider: `/provider opencode-go` runs a session on an OpenCode Go subscription, serving its chat-completions models with the reasoning efforts each one accepts, and searching the web through Exa as OpenCode itself does.

- **`opencode-go` route (new)**: a new plugin, `plugins/opencode-go`, registers the route. `/provider opencode-go` (also `/provider opencode`) asks for the key from the OpenCode console and stores it in `~/.dscode/credentials.yaml` like the other provider keys. `OPENCODE_API_KEY` in the environment takes precedence. The key is sent as a bearer token to `https://opencode.ai/zen/go/v1/chat/completions`. The provider picker, `/login opencode-go` and `/model` pick it up from the provider catalog without terminal changes. Switching from DeepSeek or OpenRouter lands on the same model when Go serves it; otherwise the switch lands on `kimi-k3`.
- **A catalog probed against the live gateway (design)**: Go's `/models` listing returns ids only. It gives no context size, image support or reasoning controls. Go also passes request fields through to each model's upstream, so what a request may contain differs by model. The catalog therefore records, per model, what the gateway accepted in September 2026. It covers the `reasoning_effort` values (GLM, Kimi K2.7 Code, LongCat and Space Bunny cannot switch thinking off, and MiMo V2.6 refuses `max`) and whether the model takes images (a text-only model answers an image with HTTP 404). Context windows follow each lab's published figure. The catalog has 19 models: DeepSeek V4 (4), GLM (4), Kimi (3), MiMo (4), LongCat, Hy (2) and Space Bunny Free. The DeepSeek rows follow DeepSeek's own API rather than a probe, because the test workspace was not set to Go's Global region.
- **Request shape**: the body keeps to OpenAI fields: `reasoning_effort` (Off sends `none`, Ultra sends `max` plus the collaboration policy) and `stream_options.include_usage`. It omits OpenRouter's extensions (`reasoning: {effort}`, `provider`, `session_id`), which Go's upstreams reject with "Extra inputs are not permitted". Each request carries the session id in `x-opencode-session` and a `dscode/<version>` user agent, as Go asks of third-party clients. Reasoning goes back to the model that produced it as `reasoning_content`. DeepSeek gets an empty one after another model's turn, because it rejects a thinking-mode tool-call turn without one.
- **Shared request loop (changed)**: the Go adapter extends the OpenRouter adapter instead of copying it. The request loop, image preparation, SSE parsing and stream translation are now parameterised by route. The route supplies its model lookup, body, headers, replay kind and the name used in error messages. OpenRouter's defaults are unchanged, and its tests pass unmodified.
- **Web search through Exa (new)**: Go has no search endpoint. A Go session's `web_search` therefore calls `web_search_exa` on Exa's hosted MCP server (`https://mcp.exa.ai/mcp`), which is what OpenCode's own client does, and that server answers without a key. An `EXA_API_KEY` in the environment or the credential store moves the calls onto that account, and a key store that cannot be read falls back to the keyless endpoint. Exa's text answer is parsed into de-duplicated sources with title and snippet. A search times out after 25 seconds, and cancellation is honoured. Routing sends only `opencode-go` sessions to Exa, because the keyless tier is Exa's free offer with no published limit. DeepSeek, OpenRouter and Grok sessions search as before.
- **Where it stops**: Go serves Qwen and MiniMax over the Anthropic messages protocol, and Grok 4.x, GPT Luna and Muse Spark over the OpenAI responses protocol. This release implements neither. Naming one of those models fails before any request with a message that names the endpoint. The footer shows no cost and no balance on this route, because Go publishes no allowance API. When the workspace is not in the Global region, Go refuses its DeepSeek models; the error now adds where to change that in the OpenCode console.

Verification: `npm run check` passed on macOS. That covers lint, both typechecks, 581 unit tests at 84.54% measured `.mjs` line coverage (nine tests are new for this route), the nine native Harness integration probes, both package tarballs and 51 evaluations. The extended `scripts/verify-login-runtime.mjs` probe boots a real Harness Host twice and checks that the `opencode-go` row saves its key, keeps it across a restart, lists the catalog with the right efforts and sends the expected request shape. With a real Go key, the adapter completed a tool call followed by a replayed answer on all 15 non-DeepSeek chat models. The DeepSeek and Qwen rows failed with their intended explanations. A live keyless Exa search returned titled, de-duplicated sources, and a cancelled search reported `WEB_ABORTED`.

What has no automated case: the DeepSeek rows were not exercised against Go, because the test workspace was not in the Global region. Image input was checked with direct gateway requests, not through the adapter's attachment path. The provider picker and `/login opencode-go` were not driven by hand in a live terminal. No model ran `web_search` inside a real Go session; routing to Exa is covered by unit cases only.
