# DSCODE 0.7.6

这版把 OpenRouter 从三个 DeepSeek 模型扩展到 pi-ai 的整个 OpenRouter 目录，并修掉让非 DeepSeek 模型跑不起来或体验变差的几处：effort 写死 DeepSeek 档位、委派只在 Ultra 下可用、费用和缓存命中率算不出来。review 的输出上限也不再压得很低。

- **OpenRouter 列出整个目录**：`/provider openrouter` 写入的配置不再只列 3 个 DeepSeek 模型，而是列出 pi-ai 目录里的全部 OpenRouter 模型（366 个，含 Anthropic、OpenAI、Google、Qwen、Kimi、GLM 等），不用手动按 id 添加。三个 DeepSeek 模型仍通过 `modelOverrides` 使用官方的 off/low/high/max 档位和 Ultra，其余模型用各自的推理档位和协议（Claude 走 `anthropic-messages`）。0.7.3～0.7.5 写入的窄配置会在打开 `/model` 或切换 provider 时自动替换；用户改过的配置不动。
- **`/model` 可以搜索**：按 `/` 或 Ctrl+F 开始搜索，输入的每个词都要匹配 provider 或模型名；搜索时输入的 `q`、`r`、`g` 只作为文字，Esc 退出并清空，↑↓ 和 Enter 照常可用。
- **OpenRouter 费用按实时价格计算**：配置了 OpenRouter key 后，从 OpenRouter 公开的模型列表读取价格（不需要 key），在数据目录缓存一天，包含缓存写入价和长提示阶梯价；没有单列缓存读写价的模型按输入价计。读取失败时保留上一份价格，DeepSeek 模型仍有固定价格兜底。
- **修复：OpenRouter 上缓存命中率一直是 `--`**：pi-ai 只在有缓存读取时才报告这个数字，一次没有该字段的调用会让整个会话的命中率变成未知；现在缺失按 0 计。
- **effort 跟随模型**：配置默认的 `high` 在模型不支持时回退到模型自己的默认值，不再让不带推理的模型（如 qwen3-coder、kimi-k2）每一轮都报错。会话卡片、`/doctor`、记忆以及 Ultra 下的 review 会请求模型支持的最接近档位，模型没有档位时不传；记忆配置接受所有标准档位名。`dscode exec --effort` 接受 `minimal`、`medium`、`xhigh`，并在开始前按模型校验。子 agent 的 effort 说明不再写死 low/high/max，`/status` 也不再对非 DeepSeek 模型显示 xhigh。
- **任何 effort 都可以委派**：`subagent` 和 `subagent_fork` 不再只在 Ultra 下提供，没有 `max` 档（因而没有 Ultra）的模型也能委派。低于 Ultra 时由提示词控制：默认自己做，只委派较大的独立部分或会挤占上下文的大范围只读调查，同一时间最多一个子 agent，选择模型支持的最低合适档位。Ultra 保留原有协作策略；`workflow` 和 `ralph` 仍不可用，三个子 agent 的并发上限对所有 effort 生效。
- **review 输出上限放宽**：不再限制 8192 个输出 token，改用模型路由的默认上限（DeepSeek 256k，OpenRouter 为目录中的模型上限）；超时从 90 秒放宽到 10 分钟，交回给 agent 的报告最多保留 64,000 个字符。

升级前退出使用同一数据目录的 DSCODE 会话：

```sh
npm install -g @toddzheng024/dscode@0.7.6
dscode update 0.7.6
```

也可从 GitHub Releases 下载 `dscode-0.7.6.tar.gz` 安装独立源码包；两种安装方式使用不同数据目录，不自动迁移会话和凭据。
