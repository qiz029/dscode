# DSCODE 0.7.5

This release makes review work in a non-Git workspace. In the evaluation `/app` was not a Git repository, so the model never received a hint to call review, and the review tool there only returned `no_repository`.

- **A non-Git workspace also gets the review hint and a diff**: before a task's first tool call, dscode snapshots the workspace into a tree inside a shadow bare repository under `DSH_HOME/review-baselines` (the workspace itself is untouched); at review time it snapshots again and diffs against the baseline for the independent review. The model can only change files through tools, so what is captured at that moment is the pre-task state. Such a workspace gets its own hint explaining that the review covers changes since the task began. `path` may narrow the range, while `staged`, `base` and `commit` still need Git.
- **Snapshot scope and limits**: it skips `.git`, `node_modules`, virtual environments and cache directories, the sensitive files review skips anyway (`.env`, keys and so on) and files over 4 MiB, and the workspace's `.gitignore` applies too; a change to those files is not reviewed. A workspace over 20,000 files or 256 MiB is not snapshotted, and review returns `no_baseline` with a hint not to call it again.
- **The baseline follows the task**: the baseline is one ref per session and survives a resume; starting a new task in the same session replaces the old baseline. Without a git executable the behaviour is unchanged: no hint is injected and review returns `no_repository`.

Exit DSCODE sessions using the same data directory before upgrading:

```sh
npm install -g @toddzheng024/dscode@0.7.5
dscode update 0.7.5
```

`dscode-0.7.5.tar.gz` can also be downloaded from GitHub Releases to install the standalone source package; the two installation forms use different data directories and never migrate sessions or credentials automatically.

Verification covers unit, integration, TUI, package build and the coverage baseline. New here: the snapshot diff includes modified and added files, excludes ignored directories/sensitive files/large files, narrows by `path`, errors on a Git scope, reads the baseline back through a new store instance, lets a new task replace the baseline, and returns `no_baseline` over the limits; plus an end-to-end test where the pre-tool-call hook establishes the baseline and the review tool then reviews the change. Whether a model follows the hint and calls review was not confirmed in a real model session.
