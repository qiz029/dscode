# DSCODE 0.7.2

这版把终端还给了用户（滚轮、拖选、复制全部原生），页脚改成两行，并修掉 macOS 上等待终端输入的命令卡死的问题。

- **终端重新掌管滚动与选择**：0.7.x 的原地全屏视口会清空 scrollback、还必须捕获鼠标才能滚轮。现在已完成的转录通过 Ink `Static` 一次性打印到终端 scrollback，滚轮、拖选、复制都是终端原生行为，`/mouse`、应用内 PageUp/PageDown 和滚轮队列随之删除；欢迎框成为第一行 scrollback，会随会话一起滚走，每轮结束画一条分隔线。**仍带旧原地视口的安装必须先刷新依赖（`npm ci`）**，启动器拒绝原地修补那份文本。
- **页脚两行**：第一行是 `● <会话标题> ｜ <权限>`（会话还没有标题时回退成 `model ｜ effort`），右侧仍钉着状态栏切换提示；第二行以 `provider: model @ effort` 开头，后面是遥测 —— `current | average | context | $花费 / $余额 🔥 | cache hit`。宽度不够时先丢 average、再丢 cache hit、再丢 current，然后模型头退成裸 `model @ effort`，再丢 context，最后才轮到模型头本身：金额永远留着。缓存命中率按档配色（<90 红、90–95 黄、95–98 绿、≥98 蓝），金额始终两位小数不带 `~`，页脚也会跟随 `/language` 的语言（之前被钉死在英文）。
- **macOS 上等待终端输入的命令不再卡到 300 秒**：固定的 inspector 现在通过读进程表（`ps`，带节流）判断「在等输入」——shell 终端的进程组必须处于睡眠、CPU 时间冻结、且不持有 socket——持久 shell 在静默五秒后中断它并说明原因。注意：这条修复作用于**仓库安装**；npm/Hub bundle 目前仍装 registry 上的 inspector 副本，把探针搬进 bundle 已经 vendor 的 `dsh-terminal-bash` 是后续项。
- 其余改动：页脚显示 DeepSeek 账户余额（`$花费 / $余额` + 高峰 🔥 / 低谷 ❄️）、沙箱提权请求可以由 agent 按确定性诊断白名单自审、每轮结束留白、verbose 恢复流式思考输出，以及 GitHub Actions 发布流水线（推 `v*` tag 自动按 bundle → Hub profile → launcher 顺序发布，手动 dispatch 可只构建、只验凭据或干跑）。

升级前退出使用同一数据目录的 DSCODE 会话：

```sh
npm install -g @toddzheng024/dscode@0.7.2
dscode update 0.7.2
```

Hub 上的 `dscode` profile 从 0.7.0 直接跳到 0.7.2——0.7.1 只发过 npm bundle，没有 Hub release 和 launcher，所以 `dscode update 0.7.1` 不存在。也可从 GitHub Releases 下载 `dscode-0.7.2.tar.gz` 安装独立源码包；两种安装方式使用不同数据目录，不自动迁移会话和凭据。

验证覆盖单元、集成、TUI、包构建、真实本机 Harness 启动，以及 Hub 安装/升级失败/回退。本次新增：页脚两行的渲染断言（32–120 列各档丢什么）、缓存配色、macOS 探针的三种结果、以及发布流水线的只读凭据检查。
