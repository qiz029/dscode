# DSCODE 0.7.2

This release gives the terminal back to the user (wheel, drag-select and copy are all native again), turns the footer into two lines, and fixes a command that waits for terminal input hanging on macOS.

- **The terminal owns scrolling and selection again**: the 0.7.x in-place full-screen viewport cleared the scrollback and had to capture the mouse to scroll the wheel. A finished transcript is now printed once into the terminal scrollback through Ink `Static`, so the wheel, drag-select and copy are native terminal behaviour, and `/mouse`, in-app PageUp/PageDown and the wheel queue were removed with it; the welcome box becomes the first scrollback line and scrolls away with the session, and each turn ends with a divider. **An installation still carrying the old in-place viewport must refresh its dependencies first (`npm ci`)**, because the launcher refuses to patch that text in place.
- **A two-line footer**: the first line is `● <session title> ｜ <permission>` (falling back to `model ｜ effort` while the session has no title), with the statusline toggle hint still pinned to the right; the second line starts with `provider: model @ effort` followed by the telemetry — `current | average | context | $cost / $balance 🔥 | cache hit`. When the width runs out it drops average first, then cache hit, then current, then the model head degrades to a bare `model @ effort`, then context goes, and only then the model head itself: the money stays to the end. The cache-hit rate is coloured by band (<90 red, 90–95 yellow, 95–98 green, ≥98 blue), money always has two decimals without a `~`, and the footer follows `/language` too (it used to be pinned to English).
- **A command waiting for terminal input no longer hangs for 300 seconds on macOS**: the fixed inspector now decides "waiting for input" by reading the process table (`ps`, throttled) — a shell terminal's process group has to be sleeping with frozen CPU time and holding no socket — and the persistent shell interrupts it after five silent seconds with the reason. Note: this fix applies to a **repository installation**; the npm/Hub bundle still installs the registry copy of the inspector, and moving the probe into the already-vendored `dsh-terminal-bash` is a follow-up.
- Other changes: the footer shows the DeepSeek account balance (`$cost / $balance` plus peak 🔥 / off-peak ❄️), a sandbox escalation request can be self-reviewed by the agent against a deterministic diagnostic allowlist, each turn leaves a blank line, verbose restores streaming thinking output, and a GitHub Actions release pipeline (pushing a `v*` tag publishes bundle → Hub profile → launcher in order, and a manual dispatch can build only, verify credentials only, or dry-run).

Exit DSCODE sessions using the same data directory before upgrading:

```sh
npm install -g @toddzheng024/dscode@0.7.2
dscode update 0.7.2
```

The `dscode` profile on the Hub jumps straight from 0.7.0 to 0.7.2 — 0.7.1 only ever shipped an npm bundle, with no Hub release and no launcher, so `dscode update 0.7.1` does not exist. `dscode-0.7.2.tar.gz` can also be downloaded from GitHub Releases to install the standalone source package; the two installation forms use different data directories and never migrate sessions or credentials automatically.

Verification covers unit, integration, TUI, package build, a real local Harness launch, and Hub install/failed upgrade/rollback. New here: rendering assertions for the two footer lines (what each band drops from 32 to 120 columns), the cache colouring, the three outcomes of the macOS probe, and the read-only credential check of the release pipeline.
