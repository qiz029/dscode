# DSCODE 0.7.9

这版让 `dscode update` 一步更新整个安装：tar 安装获得原位自升级，npm/Hub 启动器会替换自身 binary；同时接入 ESLint 10，并修复审查白名单与错误处理上的一批问题。

- tar 安装新增 `dscode update [精确版本号]`：从 GitHub Releases 下载 tar 包并按发布方 sha256 摘要校验（无摘要拒绝安装），迁移 `.runtime`、`.env` 与本地 config（release 自带的新版默认文件不被旧副本覆盖），原位换目录——`dscode` 命令路径不变，无需重新链接；旧安装保留为同级备份目录，可手动换回或丢弃。源码检出处会拒绝并提示 git pull；运行中有会话时拒绝更新，换目录前会再次检查。
- npm/Hub 安装的 `dscode update` 先用 npm 把全局 launcher 本体替换到目标版本，成功后才把 profile 升到同一版本，任一步失败都不会留下半更新状态；省略版本号时查询 npm 上的最新 launcher，有新版本就一起更新，registry 不可达时回退到当前 launcher 的推荐版本，不隐式追踪 latest。
- 仓库接入 `npm run lint`（ESLint 10 flat config）并纳入 `npm run check`；`*-panel.mjs` 等序列化进 TUI 的模板文件按其绑定方式豁免。
- 收紧自动审查的提权白名单：`sysctl -w`、赋值形 key、带参数的 `hostname`/`date` 不再被自动授予，状态可变的诊断回到人工确认。
- code review 收集 untracked 文件时，消失或不可读的文件计入 omitted 而不是让整个 review 报错；审查审计文件损坏行被跳过，不再打断之后的每次审批。
- session-bridge 的一次恢复失败只让当步 fail closed，下一步自动重试，不再永久卡死该会话的收件。
- 邮件存储与验证脚本不再在 finally 中抛错（清理失败不会掩盖成功结果或原始错误）；checks 的完整性校验与套件失败同时上报；六处 catch 补上 error cause。

本版不升级 DSH 上游依赖。

验证：`npm run check` 通过（243 项单测、44 项评估测试；完整源码覆盖率 80.29%；集成、真实 Ink UI 与安装包检查通过）。tar 自升级从本版起随包分发，更早版本的 tar 安装仍需手动换目录一次；更新过程中的会话竞态窗口已收窄到秒级但未消除（不与运行中的会话共享内核锁）。
