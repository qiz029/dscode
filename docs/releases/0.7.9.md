# DSCODE 0.7.9

This release makes `dscode update` update a whole installation in one step: a tar installation gains in-place self-upgrade, and the npm/Hub launcher replaces its own binary; it also adopts ESLint 10 and fixes a batch of problems in the review allowlist and error handling.

- A tar installation gains `dscode update [exact version]`: it downloads the tarball from GitHub Releases and verifies it against the publisher's sha256 digest (a release without a digest is refused), migrates `.runtime`, `.env` and the local config (a newer default file shipped by the release is not overwritten by the old copy), and swaps the directory in place — the `dscode` command path does not change and needs no relinking; the old installation is kept as a sibling backup directory to switch back to or discard by hand. A source checkout refuses and asks for a git pull; a running session refuses the update, and the check is repeated before the directory swap.
- For an npm/Hub installation, `dscode update` first replaces the global launcher itself with npm at the target version and only then moves the profile to the same version, so a failure in either step leaves no half-updated state; with no version it asks npm for the latest launcher and updates both when there is a newer one, falling back to the current launcher's recommended version when the registry is unreachable, never tracking latest implicitly.
- The repository adopts `npm run lint` (ESLint 10 flat config), included in `npm run check`; template files serialised into the TUI such as `*-panel.mjs` are exempted the way they are bound.
- The automatic-review escalation allowlist is tightened: `sysctl -w`, assignment-form keys, and `hostname`/`date` with an argument are no longer granted automatically, so a state-mutating diagnostic goes back to a human confirmation.
- When code review collects untracked files, a file that vanished or is unreadable counts as omitted instead of failing the whole review; a corrupt line in the review audit file is skipped instead of breaking every later approval.
- A failed session-bridge recovery now fails closed for that step only and is retried by the next step, instead of permanently wedging that session's reception.
- The email store and the verification scripts no longer throw inside `finally` (a cleanup failure cannot hide a successful result or the original error); the checks report an integrity violation and a suite failure together; six `catch` blocks gained an error cause.

This release does not upgrade the upstream DSH dependencies.

Verification: `npm run check` passes (243 unit tests, 44 evaluation tests; 80.29% complete-source coverage; integration, the real Ink UI and the package checks pass). Tar self-upgrade ships with the package from this release; an older tar installation still needs one manual directory swap. The session race window during an update is narrowed to seconds but not eliminated (no kernel lock is shared with a running session).
