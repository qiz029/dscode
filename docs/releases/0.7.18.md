# DSCODE 0.7.18

This release adds three things that let the compaction evaluation guide decisions — deterministic context fidelity, a pre-screen of discriminating cases, and separating a format failure from a model failure — and completes the first summary A/B.

- **Context fidelity (new, evaluation)**: on the context the model really saw, `retention` counts at token boundaries whether each probe's original sentence evidence (`evidence.quote`) and the words inside it are still present, writes it into `scores.jsonl`, and the report carries an `Evidence kept` column. It calls neither the model under test nor the judge, so it has no sampling variance and can be recorded on every run. On LongMemEval tier1 it explained the source of compaction loss directly: with the evidence sentence still present the pass rate is close to no compaction, while a sentence swallowed by the summary leaves only 4%–6% — and word-level retention is still 89%–92%: a summary keeps the words and loses the restatable fact.
- **Pre-screen of discriminating cases (new, evaluation)**: `--baseline <run> [--baseline-policy full]` keeps only cases where that policy was fully correct in every repeat of the baseline run with no infrastructure error; the filtered dataset is written to the new run's `dataset.json` and `manifest.json`'s `selection` records the source and the counts. Of these 100 cases, 47 were selected, saving half the non-discriminating probes in later policy comparisons.
- **A summary A/B without changing the product (new, evaluation)**: a policy may carry a `summaryInstruction`, which the evaluation-side `EvalCompactionEngine` inserts into the compaction request before the upstream summarisation instruction; without it the behaviour matches the product exactly. The first comparison (`compact-80` vs `compact-80-keepfacts`, 47 cases × 3 repeats) was a **negative result**: asking to "keep the quotable fact sentences" changed neither fidelity nor the pass rate (10 better, 11 worse) and cost slightly more. The conclusion and how to reproduce it are recorded in `eval/experiments/2026-09-longmemeval-tier1-summary-ab.md`.
- **Probe protocol retry (fix, evaluation)**: when a reply is not a single valid JSON, or the stream is cut off before the JSON closes, it retries once with a corrective hint and records it in `answerRetries` (counting towards the call ceiling); a rejected reply never enters the session, so later checkpoints are unaffected. Another run had zero of these format errors (423 checkpoints), showing that the earlier 15 `invalid-answer-json` came from the backend and model snapshot of the time rather than a general runner defect.
- **Word boundaries in evidence quoting (fix, evaluation)**: LongMemEval samples used to be hard-cut at 160 characters, leaving 87/100 evidence quotes split mid-word, which a token-boundary match then judged "not retained" (even without compaction only 55% survived). The cut is now at a word boundary, and after the fix the no-compaction policy is back to 100%; the corrected dataset is written to `eval/private/longmemeval/tier1-wordboundary.json` without overwriting the original file, and the hash check of historical runs stays valid.
- **Prebuilt release packages (new)**: `dscode-<version>-darwin-arm64.tar.gz` and `-darwin-x64.tar.gz` are source trees with the locked `node_modules` already installed, and the `curl | sh` installer and `dscode update` prefer the one for the local platform, so installing and upgrading only reaches GitHub and needs neither npm nor the npm registry — a corporate registry proxy can no longer block `npm ci`. A platform without a prebuilt package falls back to the source tarball, and `DSCODE_INSTALL_SOURCE=1` forces the choice. `npm run dist` builds all three (`DSCODE_PREBUILT_ARCHS` can narrow or skip the prebuilt packages), and the release workflow and `make attach` upload them.
- **The launching directory's `.env` no longer affects the launch (fix)**: upstream reads the launching directory's `.env` as a project layer, so a workspace file could inject variables into the agent process, and one of the names reserved for bootstrap (any `DSH_*`, `NODE_OPTIONS`, a CA path) would abort the launch with "only the launching environment may set". A pinned `dsh-app-boot` patch now drops that layer in a repository and a tar installation; the installation's own `.env` is still loaded by the launcher.

Verification: `npm run check` passes (lint, coverage, integration, packaging and evaluation all green). The new evaluation tests cover token-boundary matching for fidelity and the evidence loss after compaction, the `--baseline` selection (including across repeats and with partial evidence), and that the protocol retry only changes the compaction request's prompt while a rejected reply never enters the session; the `summaryInstruction` test confirms it appears only in the compaction request.
