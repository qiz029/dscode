# DSCODE 0.7.4

This release fixes an approval problem the evaluation exposed: under `danger-full-access` every MCP call needing approval was silently denied, and `dscode exec --approve-all` could not let it through either.

- **MCP calls work again under `danger-full-access`**: automatic review turns every MCP call other than the read-only Chrome methods into one needing approval, regardless of the current permission preset. `danger-full-access` has the `never` approval strategy, and the approval service denies outright before any `approval/request` handler runs, so MCP calls in the TUI were silently denied and the allowance from `dscode exec --approve-all` never got its turn (in the evaluation the denial and the call landed in the same millisecond). A `never` strategy no longer intercepts MCP calls; presets with an `ask` strategy such as `auto` and `ask` still send MCP calls through review or a question as before.

Exit DSCODE sessions using the same data directory before upgrading:

```sh
npm install -g @toddzheng024/dscode@0.7.4
dscode update 0.7.4
```

`dscode-0.7.4.tar.gz` can also be downloaded from GitHub Releases to install the standalone source package; the two installation forms use different data directories and never migrate sessions or credentials automatically.

Verification covers unit, integration, TUI, package build and the coverage baseline. New here: unit tests that automatic review still requires approval for an MCP call under the `ask` strategy and allows it directly under `never`, with confirmation that the test fails once the fix is removed. An MCP call was not made inside a real `dscode exec --permission danger-full-access --approve-all` session.
