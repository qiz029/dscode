# DSCODE 0.7.4

这版修掉评测暴露的一个审批问题：`danger-full-access` 下所有需要审批的 MCP 调用都会被静默拒绝，`dscode exec --approve-all` 也放行不了。

- **`danger-full-access` 下 MCP 调用恢复可用**：自动审核会把除 Chrome 只读方法以外的 MCP 调用一律改成需要审批，不看当前权限预设。`danger-full-access` 的审批策略是 `never`，审批服务在任何 `approval/request` 处理器运行之前就直接拒绝，所以 TUI 里 MCP 调用被静默拒绝，`dscode exec --approve-all` 的放行也轮不到执行（评测里拒绝和调用落在同一毫秒）。现在策略为 `never` 时不再拦截 MCP 调用；`auto`、`ask` 等 `ask` 策略的预设照旧对 MCP 调用走审核或询问。

升级前退出使用同一数据目录的 DSCODE 会话：

```sh
npm install -g @toddzheng024/dscode@0.7.4
dscode update 0.7.4
```

也可从 GitHub Releases 下载 `dscode-0.7.4.tar.gz` 安装独立源码包；两种安装方式使用不同数据目录，不自动迁移会话和凭据。

验证覆盖单元、集成、TUI、包构建与覆盖率基线。本次新增：自动审核在 `ask` 策略下对 MCP 调用仍要求审批、在 `never` 策略下直接放行的单元测试，并确认去掉修复后该测试失败。未在真实 `dscode exec --permission danger-full-access --approve-all` 会话里调用 MCP。
