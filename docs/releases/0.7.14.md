# DSCODE 0.7.14

This release connects the **Grok subscription** as a provider, turns automatic compaction into **pre-compaction** (at the threshold it no longer compacts on the spot but waits for a summary already running in the background), and fixes the code review **thinking budget**: the DeepSeek reviewer used to spend 25k–56k tokens of thought inside the 90-second deadline and write not one word of a report, so every review ended in a timeout.

- **Grok subscription**: `grok` is connected as a subscription provider. The adapter only reads the `grok` CLI's login (`~/.grok/auth.json`, which DSCODE never writes back, so it cannot knock the CLI offline by racing its refresh-token rotation), talks to `api.x.ai/v1`, and supports structured tool calls and reasoning; the model list — context window, output limit and the `low/medium/high/xhigh` bands — comes from the CLI proxy's `/v1/models`. The footer shows the subscription allowance instead of cost: the used percentage of the weekly window from `/v1/billing?format=credits` plus the local reset time, and "no usage reported" rather than a made-up number when it is unavailable.
- **Pre-compaction**: one band below the priced threshold (70% of the default 80% threshold) a background thread summarises the oldest compactable region first, **without touching disk and without a lock**; when the threshold is really reached it opens `compaction/start` and reuses that summary to commit, so the wait at the threshold is "waiting for something already running", and content added between 70% and 80% **stays verbatim after the checkpoint** instead of being folded into the summary. A summary invalidated by a manual compaction or a surface rewrite is dropped silently and the step summarises again.
- **Agent-line timestamps**: a tool card, folded thinking and a reply each start with the local `HH:MM:SS` of that line's event in a dim colour, with the block wrapping to the remaining columns.
- **Code review turns thinking off**: a review now requests `off` by default (the only band that really disables thinking). `minimal` used to land on `low` for DeepSeek, which is still a thinking mode, measuring 24k–56k reasoning tokens per call and almost certainly being cut off by the 90-second deadline; with it off the output is just the report. A model without an `off` band keeps its own default, and `DSCODE_REVIEW_EFFORT` can still override.
- **Fixes**: the `credentials` provider is mounted again in a source checkout (upstream matches the row by `name` while the patch only changed the config key, so it had only worked in the npm bundle); the composer no longer floats up after a `<Static>` flush; a running shell command keeps its own output window and poll no longer overwrites accumulated text with the current viewport (another session or a background task in the same terminal can no longer make it report "beginning dropped" wrongly).

Verification: `npm run check` is green — 262 unit tests (7,595/9,257 first-party lines, 82.05%), the integration probes (session bridge, messaging, runtime foundations, session cards, memory, login runtime, exec), the package checks and 46 evaluation tests; this environment cannot allocate a PTY, so the case that blocks a terminal in the exec probe is skipped by the existing convention. Whether the code-review change takes effect is **not confirmed on a real machine**: this session's process had loaded the old plugin module before the file changed, so `review` still ended in a 90-second timeout; the new code was verified offline to resolve to `off` on the real DeepSeek adapter (→ wire `thinking: disabled`), and on the same route a forced-disabled `session-title` call history shows 28/30 calls with 0 reasoning tokens.
