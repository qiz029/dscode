# DSCODE 0.7.14

这版把 **Grok 订阅**接成 provider，把自动压缩改成**预压缩**（到阈值不再现压缩、而是等在后台跑完的摘要），并修掉代码审查的**思考预算**问题：原先 DeepSeek 评审在 90 秒期限里把 2.5–5.6 万 token 全花在思考上、报告一个字没写，于是每次 review 都以超时收场。

- **Grok 订阅**：`grok` 作为订阅型 provider 接入。适配器只读 `grok` CLI 的登录（`~/.grok/auth.json`，DSCODE 从不写回，避免与 CLI 的 refresh token 轮换互相踢下线），走 `api.x.ai/v1`，支持结构化 tool call 与 reasoning；模型列表——上下文窗口、输出上限与 `low/medium/high/xhigh` 档位——取自 CLI 代理的 `/v1/models`。footer 不再显示费用而是订阅额度：`/v1/billing?format=credits` 的周窗口已用百分比加本地重置时间，拿不到就显示「无用量上报」而不是编一个数。
- **预压缩**：价格化阈值以下一个档位（默认 80% 阈值的 70%）先用后台线程把最旧可压区间摘要出来，**不落盘、不加锁**；真正到达阈值时才开 `compaction/start` 并复用这份摘要提交，所以阈值处的等待是「等已在跑的事」，且 70%→80% 之间新增的内容**原样留在 checkpoint 之后**，不会被并进摘要。摘要被手动压缩或 surface 重写作废时静默丢弃，该 step 重新摘要。
- **agent 行时间戳**：tool card、折叠的 thinking 与回复各自以本地 `HH:MM:SS`（该行事件时间）开头、暗色显示，块宽按剩余列数换行。
- **代码审查关思考**：评审默认请求 `off`（唯一真正关掉 thinking 的档位）。此前 `minimal` 在 DeepSeek 上落到 `low`，仍是思考模式，实测 24k–56k reasoning token／次，90 秒期限几乎必然被掐断；关掉后输出只剩报告本身。模型没有 `off` 档时保持自身默认，`DSCODE_REVIEW_EFFORT` 仍可覆盖。
- **修复**：源码检出下 `credentials` provider 重新挂上（上游行按 `name` 匹配、补丁只改配置键，此前只有 npm bundle 生效）；composer 在 `<Static>` 静态 flush 后不再上浮；运行中的 shell 命令各自持有输出窗口，poll 不再用当前视口覆盖已累积文本（同终端上的其他会话/后台任务不会再让它误报「开头被丢弃」）。

验证：`npm run check` 全绿——262 项单测（首方源码 7595/9257 行、82.05%）、集成探针（session bridge、messaging、runtime foundations、session cards、memory、login runtime、exec）、安装包检查与 46 项评估测试；本环境无法分配 PTY，exec 探针里阻塞终端的那条用例按既有约定跳过。代码审查的生效验证**未实机确认**：本会话进程在我改文件之前就加载了旧插件模块，`review` 仍以 90 秒超时收场；已离线验证新代码在真实 DeepSeek 适配器上解析为 `off`（→ wire `thinking: disabled`），且同一路由上强制 disabled 的 `session-title` 调用历史里 28/30 次 reasoning token 为 0。
