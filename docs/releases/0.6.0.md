# DSCODE 0.6.0

This release focuses on unattended runs, a readable identity for child agents, and the release experience.

- `dscode exec "prompt"` runs a complete dscode agent turn without opening the TUI: the same preset, tools, skills, MCP and memory. The reply streams to stdout, tool activity and the session id go to stderr, and the exit code reflects the turn's result. It supports a stdin prompt, `--json`, `--resume`, `--effort`, `--model`, `--permission`, `--approve-all` and `--timeout`. An approval request that would fall back to a human is denied by default when nobody is present.
- A parent agent must name every child agent (1 to 10 characters of letters, digits or underscores, starting and ending with a letter). A child agent shows as `/name · description` in the agents line and `/agents`; `send_message` and `interrupt_agent` accept `/name`, a child refers to its parent as `/`, and live children of one parent cannot share a name.
- The welcome box became a three-shade pixel snowflake, 24×24 on terminals of 26 rows or more and 22×22 on 24 to 25 rows; while the agent works the bottom activity line is a snowflake orbit animation; the turn divider spans the full line.
- Prompt tuning: the persona gained rules for reply language, the boundary between judging and asking, complete delivery and honest reporting; the shell policy keeps only a delegation summary and leaves the detail to the Ultra request policy; the email guidance no longer embeds real contacts.
- The publish script can read a granular npm token from the macOS keychain and hand it to npm through a one-off temporary config, with no login and no one-time code; `npm run publish:token store|check|remove` manages that token.

Exit DSCODE sessions using the same data directory before upgrading:

```sh
npm install -g @toddzheng024/dscode@0.6.0
dscode update 0.6.0
```

`dscode-0.6.0.tar.gz` can also be downloaded from GitHub Releases to install the standalone source package. The two installation forms use different data directories and never migrate sessions or credentials automatically.

Verification covers unit, integration (including an end-to-end exec probe with a fake model), TUI, package build, a real local Harness launch and Hub install/rollback. `dscode exec` was only smoke-tested against a real model with a single sentence; child-agent naming survives only for display in an old session after a restart, and `/name` addressing needs a child created in the same process.
