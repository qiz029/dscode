# DSCODE 0.7.17

This release replaces the compaction engine's "build-time rewrite of upstream source" with a "subclass override", restores all six languages in `/language`, and re-aims the compaction evaluation at the production engine.

- **The compaction engine became a subclass override (refactor, behaviour unchanged)**: automatic compaction used to be written into `@deepseek-ai/dsh-compaction-basic`'s source by four `replaceOnce` patches, which could break on any upstream upgrade. The policy now lives in our own `plugins/compaction/engine.mjs`: `DscodeCompactionEngine` extends the upstream engine and overrides only `compactIfNeeded` (threshold pricing, completion budget, prefetch, prune-on-overflow first) and `summarize` (the injection point for a prefetched summary); the durable transaction, the `compaction/start|end` markers and the stability check stay with upstream `compactRegion`. Distribution no longer vendors that package, and nothing rewrites its source at install time.
- **`/language` regained all six languages (fix)**: after our own terminal took over, `/language` fell back to the upstream implementation with only en/zh, while DSCODE's own message tables had always supported `en`, `zh-CN`, `zh-TW`, `ja`, `ko` and `es` — yet the panel listed two entries and `/language ja` was silently stored as English. The list, the argument parsing and the `language.json` persistence now all follow `plugins/i18n`: `zh`, `jp` and `繁體中文` resolve through the alias table, and a stored `zh` upgrades to `zh-CN`. The terminal's own skeleton copy still has only English and Simplified Chinese, so under another language the skeleton is English and DSCODE's own copy uses the chosen language — exactly the semantics `/language` always promised.
- **The compaction evaluation re-aimed at the production engine (fix)**: after the subclassing the evaluation harness still mounted the unpatched upstream engine, which meant it no longer tested the production configuration; it now mounts `DscodeCompactionEngine` and records the engine source hash, and the judge model is decoupled from the model under test.
- **The evaluation window on OpenRouter routes (fix)**: `OpenRouterAdapter` reported the 1M window from the live listing, lifting the threshold above any replayed history so compaction never triggered; a new window wrapper reports the window the harness actually executes with.
- **Judge parsing tolerance (fix)**: if the judge wrote one sentence before the JSON object or wrapped it in a fence, a whole batch of verdicts was recorded as "unscored", failing the calibration (10/14, 6/14 and 4/14 across three models). The parser now extracts the outermost object, and the calibration passes 14/14.
- **A prefetch wait no longer swallows the compaction indicator (fix)**: submitting a compaction while a prefetch was still running used to wait for the summary before entering the transaction, and the TUI showed no compaction indicator during that wait. The wait now happens after the transaction's open marker, so the indicator shows as usual; a failed prefetch or a rewritten span falls back to a just-in-time summary instead of failing the transaction.

Verification: `npm run check` passes (lint clean; unit, integration, packaging and evaluation all green). The evaluation fixes come with real contract tests — the harness mounts the production engine, the evaluation window follows what the harness executes, and the judge parsing tolerates noise — plus engine-level regressions: threshold pricing and the completion budget still apply on the pressure path, an overflow the prune already covers skips the summary, and a prefetch commits after the marker opens and falls back when rewritten. The `/language` side gained terminal assertions: the six-language list matches DSCODE's message table item by item, alias resolution works, an old `zh` normalises to `zh-CN`, and the skeleton copy falls back to English under the other languages.
