# DSCODE 0.7.3

这版加入 OpenRouter：`/provider` 在 DeepSeek 官方 API 和 OpenRouter 之间切换同一套 DeepSeek 模型；同时修掉评测暴露的几处 harness 问题——费用账本没有耗时、部分模型调用没入账、review 跳过已合并的改动、npm 启动器缺少 `dscode exec`。

- **`/provider [deepseek|openrouter]`**：不带参数时打开选择器，显示每个 provider 的 key 状态。第一次切到 OpenRouter 会在设置文档里声明 pi-ai 的 `openrouter` 路由（DeepSeek V4 Flash、V4 Pro、V4 Flash Vision Exp；已有的 `openrouter` 配置不会被覆盖，之后可在 `/model` → `a` 里修改），缺 key 时弹出输入框、保存后继续切换，并落到当前模型的对应型号、保留当前 effort（目标不支持时用模型默认）。运行中的回合需先停止。
- **`/login [deepseek|openrouter]`**：可保存任一 provider 的 key，不带参数时针对当前 provider。`OPENROUTER_API_KEY` 与 `DEEPSEEK_API_KEY` 一样存进 `~/.dscode/credentials.yaml`（`0600`，跨项目和版本共用），环境变量优先。参数不是 provider 名时直接拒绝，且不会回显（防止误贴 key）。
- **OpenRouter 上也能用 Ultra**：pi-ai adapter 像 DeepSeek adapter 一样打补丁并随 bundle vendor。Ultra 在 OpenRouter 上发送 `xhigh` 并附带协作策略，低于 Ultra 时不提供委派工具。OpenRouter 路由提供与官方一致的 off/low/high/max 档位，`low` 以 `high` 发送（DeepSeek 本身就这样处理 low），所以会话卡片和子 agent 的 low 请求照常工作，`/effort` 也保留档位条。
- **页脚跟随当前 provider**：余额显示该 provider 的（OpenRouter 为 credits 减 usage），OpenRouter 调用按固定 pi-ai 目录的标价估算（账本 `priceVersion` 为 `openrouter-pi-ai-0.85.1`），🔥/❄️ 峰谷标记只对 DeepSeek 显示。`/status` 会写明 Ultra 在各路由上的实际 wire effort；缺凭据的错误提示改为指向 `/login`。修复：模型 id 自带厂商段（`openrouter/deepseek/deepseek-v4-flash`）时 `/effort` 找不到模型。
- **账本记录每次模型调用的耗时**：之前 `end` 行沿用开始时的 `time`，单次耗时永远是 0。现在 `end` 行新增 `endTime` 与 `firstTokenTime`（首个文本、推理或工具参数增量），`time` 仍是开始时刻（用于定价）。
- **所有代表会话发起的模型调用都入账**：review 工具与 `/review`、记忆抽取与整理、会话卡片和 `/doctor` 之前不带 `sessionId`，没有进账本。现在它们带着各自的 `purpose` 计入所属会话；归属通过异步上下文传递，而不是在请求里加 `sessionId`（那会顺带触发会话日志投递、缓存亲和和只针对 agent 的提示词改写）。压缩和会话标题原本就已入账。
- **review 不再跳过已提交或已合并的工作**：没有未提交改动时，默认范围改为审核本次任务开始以来的提交（从 HEAD 的 reflog 读出任务开始时的 HEAD）；`--commit` 审核 merge commit 时对第一个父提交做 diff，不再得到空的 combined diff。
- **npm 启动器提供 `dscode exec`**：用已安装的 Hub profile 运行 exec，选项、stdin 提示词和退出码与源码版一致；尚未安装时先安装，安装输出走 stderr，保证 stdout 可管道使用。

升级前退出使用同一数据目录的 DSCODE 会话：

```sh
npm install -g @toddzheng024/dscode@0.7.3
dscode update 0.7.3
```

也可从 GitHub Releases 下载 `dscode-0.7.3.tar.gz` 安装独立源码包；两种安装方式使用不同数据目录，不自动迁移会话和凭据。

验证覆盖单元、集成、TUI、包构建与覆盖率基线。本次新增：`/provider` 选择器与 `/login` 参数的 Ink 渲染测试；真实 Host 中声明 OpenRouter 路由、保存并重新加载两个 key，并在发出网络请求前截获 OpenRouter 请求，核对 URL、key、effort、工具与 Ultra 策略；账本耗时与异步归属测试，以及真实 Host 中会话卡片调用计入会话账本；no-ff 合并仓库下的 review 回退；启动器 `exec` 的退出码与参数透传。未做真实 OpenRouter 调用。
