# DSCODE 0.7.3

This release adds OpenRouter: `/provider` switches the same set of DeepSeek models between the official DeepSeek API and OpenRouter; it also fixes several harness problems the evaluation exposed — a cost ledger with no elapsed time, model calls missing from the ledger, review skipping merged changes, and the npm launcher lacking `dscode exec`.

- **`/provider [deepseek|openrouter]`**: with no argument it opens a picker showing each provider's key status. The first switch to OpenRouter declares pi-ai's `openrouter` route in the settings document (DeepSeek V4 Flash, V4 Pro, V4 Flash Vision Exp; an existing `openrouter` configuration is not overwritten and can be edited later in `/model` → `a`); when the key is missing it raises an input box and continues the switch after saving, landing on the corresponding model of the current one and keeping the current effort (the model default when the target does not support it). A running turn has to be stopped first.
- **`/login [deepseek|openrouter]`**: saves either provider's key, targeting the current provider when called without an argument. `OPENROUTER_API_KEY` is stored in `~/.dscode/credentials.yaml` like `DEEPSEEK_API_KEY` (`0600`, shared across projects and versions), and an environment variable takes precedence. An argument that is not a provider name is refused outright and never echoed (so a key pasted by mistake is not printed).
- **Ultra works on OpenRouter too**: the pi-ai adapter is patched and vendored with the bundle like the DeepSeek adapter. Ultra on OpenRouter sends `xhigh` with the collaboration policy, and below Ultra no delegation tools are offered. The OpenRouter route provides off/low/high/max like the official one, with `low` sent as `high` (DeepSeek handles low that way itself), so session cards and child-agent low requests work as usual and `/effort` keeps its band bar.
- **The footer follows the current provider**: the balance shows that provider's (for OpenRouter, credits minus usage); an OpenRouter call is estimated from the fixed pi-ai catalogue prices (ledger `priceVersion` `openrouter-pi-ai-0.85.1`), and the 🔥/❄️ peak/off-peak marks are shown for DeepSeek only. `/status` states the actual wire effort of Ultra on each route; a missing-credential error now points at `/login`. Fix: when a model id carries a vendor segment (`openrouter/deepseek/deepseek-v4-flash`), `/effort` could not find the model.
- **The ledger records the elapsed time of every model call**: an `end` row used to reuse the start's `time`, so a single call always took 0. An `end` row now carries `endTime` and `firstTokenTime` (the first text, reasoning or tool-argument increment), while `time` is still the start (used for pricing).
- **Every model call made on behalf of a session enters the ledger**: the review tool and `/review`, memory extraction and consolidation, session cards and `/doctor` used to carry no `sessionId` and never reached the ledger. They now count towards their session with their own `purpose`; the attribution travels through async context rather than adding a `sessionId` to the request (which would also trigger session-log delivery, cache affinity and agent-only prompt rewriting). Compaction and session titles were already recorded.
- **Review no longer skips committed or merged work**: with no uncommitted change, the default scope becomes the commits since this task began (the task's starting HEAD read from HEAD's reflog); `--commit` on a merge commit now diffs against its first parent instead of producing an empty combined diff.
- **The npm launcher provides `dscode exec`**: it runs exec with the installed Hub profile, with the same options, stdin prompt and exit code as the source form; when it is not installed yet it installs first, with the install output on stderr so stdout stays pipeable.

Exit DSCODE sessions using the same data directory before upgrading:

```sh
npm install -g @toddzheng024/dscode@0.7.3
dscode update 0.7.3
```

`dscode-0.7.3.tar.gz` can also be downloaded from GitHub Releases to install the standalone source package; the two installation forms use different data directories and never migrate sessions or credentials automatically.

Verification covers unit, integration, TUI, package build and the coverage baseline. New here: Ink rendering tests for the `/provider` picker and `/login` arguments; in a real Host, declaring the OpenRouter route, saving and reloading both keys, and intercepting an OpenRouter request before it goes out to check the URL, key, effort, tools and Ultra policy; ledger elapsed-time and async-attribution tests, plus session-card calls counting towards the session ledger in a real Host; the review fallback in a no-ff merge repository; and the launcher `exec` exit code and argument passthrough. No real OpenRouter call was made.
