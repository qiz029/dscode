# DSCODE 0.7.34

This release fixes Desktop plugin activation during a normal application launch without an exported `DSH_HOME`.

- **Default Desktop home:** workspace discovery, email, scheduling and automatic permission review previously refused to activate unless `DSH_HOME` was explicitly set. They now use the same native home resolver as Harness: a nonblank override, including supported tilde paths, or `~/.dsh`. Users seeing “4 entries did not activate” in 0.7.33 can install `@toddzheng024/dscode-desktop@0.7.34` and enable it again. No shell environment setup is required.
- **Consistent local state:** browser permissions/configuration, memory, session cards and messaging, delegation, review baselines, provider caches, diagnostics and usage resolve that same home. Explicit memory/audit directories remain supported, and the terminal launcher still translates `DSCODE_HOME` into its native Harness home. Shared account credentials and mail keep their existing locations. Old fallback data is not migrated automatically.
- **Installation qualification:** public installation now deliberately omits `DSH_HOME` and checks workspace, email, scheduling and automatic-review activation. A package cannot pass the publication gate using only an explicitly configured home. Native Host and signed macOS lifecycle verifiers also accept a default-home scenario. The earlier 0.7.33 checks set `DSH_HOME`, which concealed this activation failure.
- **Distribution maintenance:** this release includes bounded retries for npm-to-Hub propagation and the Desktop/Hub demo guide added after 0.7.33. Versioned release notes, checksums, compatibility and installation instructions continue to ship with the package.

Verification: the default-home native Host reproduced the original activation
failure before the fix and passed startup/restart after it. The signed macOS
application passed installation, upgrade, incompatible-update refusal, removal
and reinstallation with `DSH_HOME` absent, including state preservation and
browser checks. `npm run check` passed 1,073 unit/component cases at 80.17%
full-source line coverage, both TypeScript checks, native integration, package
checks and 63 eval cases. Eight focused home-resolution/release-gate tests also
passed. The exact Desktop candidate passed native Host startup/restart and
browser qualification. Installation receipts and public release status are
recorded in the [verification record](https://github.com/qiz029/dscode/blob/main/docs/verification.md).

The Desktop target remains macOS Apple Silicon with Harness runtime 0.2.0-rc.2.
Live-model task quality, native Computer Use Accessibility qualification and
other platform/runtime combinations are not established by these checks. This
release does not provide a standalone DMG or migrate old fallback data.
