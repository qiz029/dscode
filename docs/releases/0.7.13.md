# DSCODE 0.7.13

This release replaces "text-patching upstream build output" with **vendor takeover**: `packages/tui` carries `dsh-code` 1.2.0's TypeScript source directly, and all 27 DSCODE changes live as source rather than patch text; it also fixes three problems: the extra exclamation mark in shell mode, the footer width counting a variation selector as a column, and the SQLite experimental notice printed at startup.

- **Vendor takeover**: the upstream source lives in `packages/tui` (61 files under `src`), the repository root depends on it through `file:packages/tui`, and `node_modules/dsh-code` is only a symlink, so an everyday change needs **no build** and takes effect immediately. The 27 patch scripts, 6 UI verification scripts and `probe:tui` all retired, taking `scripts/patch-*.mjs` from 32 down to 6 (only the host-side runtime/Ink/stdin/compaction patches remain).
- **The release shape became compiled**: Node refuses to strip types from a file under `node_modules`, so packaging uses `scripts/build-tui.mjs` to transpile `src` into `lib` file by file (no bundling, no minification), and both the npm bundle and the `.dshprofile` carry the compiled output; a repository checkout still runs the source directly.
- **Shell mode hides the exclamation mark**: a `!cmd` draft already has the brand-coloured rounded border and the `! shell mode · esc exits` hint, so the editor no longer draws that routing prefix and the cursor moves one column left; submit routing, the paste-collapse marker, command completion and the line budget still read the real draft.
- **Width fix**: `displayWidth` counted zero-width characters (combining marks, variation selectors) as one column, so `❄️` (U+2744 + U+FE0F) counted as 3 — the footer's provider budget therefore swung by one column with DeepSeek's peak/off-peak periods, and that assertion failed at random off-peak. Zero-width characters now count 0, and the footer budget no longer swings with the period.
- **Quiet startup**: every DSH child the harness starts now carries `--disable-warning=ExperimentalWarning` (prepended ahead of the node arguments the caller passes), so the `node:sqlite` experimental notice is no longer printed at startup; the `exec` path no longer passes the same flag twice.
- **Test infrastructure**: the test fixture now symlinks `node_modules/dsh-code` to `packages/tui` (matching the repository and the resolution path of a real run), where the integration suite had been failing entirely because of the type-stripping restriction; the coverage inventory excludes `packages/tui/lib`, the compiled output, taking the first-party inventory back to 8,094 lines.

Verification: `npm run check` is green — 246 unit tests (82.98% first-party line coverage), 7 integration probes (session bridge, messaging, runtime foundations, session cards, memory, login runtime, exec), the package checks and 44 evaluation tests. Real-TTY interaction is still unverified (this environment has no pty, which is also why `EXEC_PROBE` skips the cases that block a terminal).
