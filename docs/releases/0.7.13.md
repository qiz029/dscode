# DSCODE 0.7.13

这版把终端从「给上游打包产物打文本补丁」换成 **vendor 接管**：`packages/tui` 直接携带 `dsh-code` 1.2.0 的 TypeScript 源码，DSCODE 的 27 项改动全部落成源码而非补丁文本；同时修掉 shell 模式里多出来的感叹号、footer 宽度把变体选择符当一列、启动时打印 SQLite 实验性提示三处问题。

- **vendor 接管**：上游源码放在 `packages/tui`（`src` 61 个文件），仓库根以 `file:packages/tui` 依赖它，`node_modules/dsh-code` 只是软链，因此日常改动**零构建**、改完即生效。27 个补丁脚本、6 个 UI 验证脚本与 `probe:tui` 一并退役，`scripts/patch-*.mjs` 从 32 个降到 6 个（只剩 host 侧 runtime/Ink/stdin/compaction 补丁）。
- **发布形态改为编译**：Node 拒绝对 `node_modules` 下的文件做类型剥离，所以打包时用 `scripts/build-tui.mjs` 把 `src` 逐文件转译成 `lib`（不打包、不压缩），npm bundle 与 `.dshprofile` 都携带编译产物；仓库检出仍直接跑源码。
- **shell 模式隐藏感叹号**：`!cmd` 草稿已有品牌色圆角边框与 `! shell mode · esc exits` 提示，编辑器不再绘制那枚路由前缀，光标随之左移一列；提交路由、粘贴折叠标记、命令补全与行数预算仍读真实草稿。
- **宽度修正**：`displayWidth` 把零宽字符（组合符号、变体选择符）计成一列，导致 `❄️`（U+2744 + U+FE0F）按 3 列计——footer 的 provider 预算因此随 DeepSeek 峰谷时段摆动一列，off-peak 时那条断言会随机失败。现在零宽字符计 0，footer 预算不再随峰谷时段摆动。
- **启动安静**：harness 启动的每个 DSH 子进程都带上 `--disable-warning=ExperimentalWarning`（该 flag 前置到调用方传入的 node 参数之前），启动时不再打印 `node:sqlite` 的实验性提示；`exec` 路径不再重复传同一 flag。
- **测试基础设施**：测试 fixture 改为把 `node_modules/dsh-code` 软链到 `packages/tui`（与仓库、与真实运行的解析路径一致），集成套件此前因类型剥离限制整条挂掉；覆盖率清单排除 `packages/tui/lib` 这份编译产物，首方清单回到 8,094 行。

验证：`npm run check` 全绿——246 项单测（首方行覆盖 82.98%）、7 项集成探针（session bridge、messaging、runtime foundations、session cards、memory、login runtime、exec）、安装包检查与 44 项评估测试。实机 TTY 交互仍未验证（本环境无 pty，`EXEC_PROBE` 亦据此跳过阻塞终端的用例）。
