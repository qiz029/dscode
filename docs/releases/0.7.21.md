# DSCODE 0.7.21

This release makes the footer geometry follow the terminal width alone, adds hidden clock marks for arriving messages and turn boundaries, and adds `/btw`: answer a question in a side conversation immediately, without merging the answer into the main line.

- **Footer geometry no longer moves with the values (fix)**: the permission badge is anchored to the right edge of the first line, the `shift+tab` hint keeps its columns (reserved even while it is not shown during a run), and every live figure (turn/step counts, the various durations, tps, tokens, cache hit, context reading) is right-aligned inside its own fixed column, with an empty reading rendered as a `--` placeholder instead of the whole group disappearing. Previously any value change made the badge drift sideways (measured on one screen from column 75 to column 56) and a group appear or disappear with a threshold; now only the terminal width decides the degradation order. The tps/context/cache figures inside the telemetry run are fixed-width too, reserving those 6 columns for their slots, so the fixed width does not squeeze out a figure that used to fit; the money pair (cost/balance) stays unfixed — measured, reserving columns for a number that crosses a digit boundary only a few times per session squeezes out per-second tps at common widths.
- **Hidden clock marks (new `dscode-time-marks` plugin)**: every claimed message and every just-closed turn gains one line in the model context: `Time mark: 2026-09-19T01:58:34-07:00[America/Los_Angeles] — steer relay from session:abc arrived, waited 6m24s (composed ...)`. It is plugin-sourced context that the terminal does not render at all (reusing the existing hide-by-producer rule) and it rewrites no message body; it is injected only when an arrival or a turn end really happened, so a pure tool loop pays nothing. A relay message's `source` now carries `label`/`mode`/`composedAt`, so the queueing time has evidence to report.
- **`/btw` side question (new)**: `/btw <question>` immediately creates a child session that inherits the main session's history (seeded to the most recent completed turn; with a prefix over 400 events, or no completed turn yet, it degrades to a background summary of at most 1200 characters), runs with the `read-only` permission preset at the lowest available effort, and streams the answer into the `/btw` panel (`esc` closes it, `←/→` switches between several, and the oldest finished run retires automatically). The side session carries `parentSession` and `origin: subagent`, so it generates no session card and is a read-only row in the session list; **its content never enters the main transcript or the main model context**. The child session is released when you switch session or exit.

Verification: `npm run lint` clean; `npm run test:unit` 351/351; `npm run test:package` and `npm run test:integration` (seven probes) pass. The new and extended tests cover: the segment columns and the badge column staying put across early and late values at one width, no overflow frame by frame from 36 to 240 columns, a larger telemetry number not moving later segments, the clock-mark seed degradation and brief budget, and `/btw` panel rendering with `esc` closing it. The `/btw` kernel path (really creating a child session and streaming into the panel) has no automated end-to-end case yet and relies on a real-machine check.
