# DSCODE 0.7.30

This release adds a coordinator mode: `/delegate` has the main agent plan a task on a board with priorities and dependencies, run the parts as child agents in isolated Git worktrees, verify each result and merge what it accepts. `/delegate-dashboard` shows that board as a kanban. It also raises the child cap and redraws the welcome snowflake.

- **Child cap by effort (changed)**: a parent can now run five direct children at once below Ultra and twenty at Ultra, instead of three at every effort. The runtime reads the parent's effort each time it launches or wakes a child, so dropping out of Ultra brings the lower cap back at once. Admission reservations still stop concurrent launches from racing past the cap. One delegation level is unchanged. The below-Ultra shell policy still asks for one child at a time outside `/delegate`; only the runtime ceiling moved.
- **`/delegate <task>` (new)**: the main agent becomes the coordinator. The command only checks that the session starts at a clean Git repository root and is not a child agent. It then queues the task with a fixed coordinator protocol. The transcript shows it as one `/delegate …` line, not the protocol text. Planning, dispatch, verification and merging are the model following that protocol. The runtime enforces what it can: the child cap, one delegation level, dependency order at launch, and the board itself. Children work only in their own worktree, leave their changes uncommitted, and ask the main agent with `send_message` to `/` when they are blocked.
- **Delegate board (new)**: the `delegate_board` tool records each task with a title, its planned child name, a priority (`high`, `normal`, `low`) and the tasks it depends on. The board rejects dependency cycles. A pending task is ready once every dependency is complete, and launching a blocked task is refused before it takes a slot. Ready tasks are ordered by effective priority: a task's own priority or that of any open task waiting on it, whichever is higher. Work that unblocks a high-priority task therefore goes first. Launching a child under a planned name moves its task to running. Running and verifying come from the child's live status, not from what the model last reported. A task is completed only with the main agent's verification evidence. Dropping a task releases whatever waited on it. Children never see the tool. Boards are kept per session under `$DSH_HOME/delegate-boards/` and survive a restart. A new `/delegate` clears a board whose tasks are all finished.
- **Board state as messages, not the system prompt (design)**: the coordinator receives the board and its free slots as a message ahead of its next step, and only when the board changed. Rewriting the system prompt on every change would have invalidated the provider's prompt cache for the whole conversation each time a child started, settled or asked a question. The terminal hides these messages.
- **Dependencies across worktrees**: every worktree starts at `HEAD`, and merging waits until every task is complete. A dependent task's child therefore first applies its dependencies' verified diffs from the worktree paths the board recorded. It then commits them as a baseline on its detached HEAD, which never reaches a branch. At the end the main agent merges complete tasks in dependency order with `git apply --3way`, so each task contributes only its own changes. The result is left staged and uncommitted. Merging waits for the whole board because a new worktree needs a clean main workspace.
- **`/delegate-dashboard` (new)**: a popup kanban with Pending, Running, Verifying and Complete columns, divided by vertical rules.
  - Every task is its own bordered card in its column's colour, with a status glyph, id, child name and title. `▲` marks high priority and `▼` low.
  - A blocked card is grey with a hollow `◌` and names what it waits on. A child waiting on the main agent has an amber card with a `?` badge and leads its column.
  - The title row carries a child-slot meter and completion progress. It refreshes every second, and Esc or q closes it.
  - On a short terminal every card folds to one line so more fit, and a narrow terminal stacks the columns. English and Chinese strings are included; other interface languages fall back to English.
- **Welcome snowflake (redrawn)**: the header mark is now generated from snowflake geometry. Six arms sit 60° apart around a bright hexagonal crystal, each with one branch pair parallel to its neighbours. The 30° arms are smoothed so they read as single lines. Both sizes stay mirror-symmetric, and the core → arms → branches ripple is unchanged.

Verification completed before tagging: `npm run check` passed on macOS (lint, both typechecks, 572 unit tests at 84.23% measured `.mjs` line coverage, the nine native Harness integration probes, both package tarballs and 51 evaluations). After that run, one sentence was added to the `/delegate` protocol text (the main agent tells a dependent child that its worktree-local baseline commit is authorised), and the affected suites and lint were rerun. The new behaviour has unit cases for the cap boundaries at both efforts, the `/delegate` preconditions and its notice-form message, and board transitions. They also cover persistence, dependency resolution, cycles, launch refusal, priority inheritance, released dependents, the injected board messages (including that an unchanged board is not re-sent) and the dashboard rendered through Ink at wide, short and narrow sizes. The worktree merge recipe, including a dependent task's baseline commit and dependency-order merging, was exercised against real Git repositories.

What has no automated case here: no model was driven through `/delegate`, so whether a model follows the coordinator protocol end to end — planning dependencies, dispatching in order, verifying before completing, merging in order — is unverified. The interactive TUI was not driven by hand; the dashboard and the snowflake were checked as rendered frames rather than in a live terminal. The dashboard stays within the shared half-screen panel height.
