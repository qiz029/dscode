# DSCODE 0.7.7

This release replaces pi-ai with DSCODE's own adapter for OpenRouter and closes the gaps found after 0.7.6: an upstream error returned in the stream was not retried, the actual charge was computed inaccurately, web search could only go through DeepSeek, and session titles and automatic approval often failed on a reasoning model. It also improves the compaction display and thresholds and the `/provider` and `/model` interaction.

- **OpenRouter gets its own adapter**: it calls OpenRouter's chat completions directly, and the model list, context windows, reasoning bands and prices all come from OpenRouter's live `/api/v1/models`, cached in the data directory for a day, so a new model needs no release; the first model query waits at most 10 seconds. DeepSeek, GLM, Kimi and Qwen are adapted and tested, and other tool-calling models work on a best-effort basis. Each model uses its own reasoning bands: DeepSeek V4 keeps the official off/low/high/max, a model supporting max additionally offers Ultra, and reasoning content is passed back verbatim through `reasoning_details`.
- **Routing is left to OpenRouter**: every request carries `session_id`, so one session stays on one upstream as far as possible and keeps its cache; only providers that support all request parameters and are not fp4-quantised are chosen (Kimi's native INT4 is kept). Qwen gets explicit cache breakpoints on the system message and the latest user message.
- **Errors follow OpenRouter's error codes**: an upstream error returned in the stream (such as 502) is retried, 429 reads `Retry-After`, 402 is recognised as insufficient credit, and an over-long context triggers a compaction and retry.
- **Accounting follows the actual charge**: session cost uses the `usage.cost` OpenRouter returns (including BYOK fees and the different upstream prices), falling back to a price-table estimate only when it is unavailable.
- **Web search follows the provider**: an OpenRouter session searches through OpenRouter's web plugin (Exa), while a DeepSeek session still uses DeepSeek; a user with only an OpenRouter key can search too.
- **`/openrouter` account panel**: it shows the account balance, the current key's allowance and today's/this week's/this month's spend; with a management key configured it also shows the usage of every API key and the spend of the last 30 days by model and by actual provider. After `/provider openrouter` or `/login openrouter` saves an API key it offers an optional management-key step, validated against OpenRouter before saving and used for reading only. The footer balance reads the account balance and falls back to the key's remaining allowance when the key is refused.
- **Compaction display and thresholds**: while compaction runs it shows a self-playing Tetris animation and "compacting the context, please wait" (following `/language`). The automatic compaction threshold is banded by the ratio of a model's cache-read price to its input price: below 0.1 it compacts at 90%, below 0.5 at 80%, otherwise at 60%; an unavailable price keeps 80%, and an explicitly configured threshold wins. Switching to a model in `/model` that would trigger a compaction asks for confirmation first.
- **`/model` searches directly**: typing immediately after opening searches, every character re-ranks with BM25 (model name weighted highest, then id and provider), and the word being typed is matched as a prefix. A search change does not focus, Enter or an arrow key focuses the first result, and Enter while focused selects it; Esc clears the search first and then closes, Tab opens the provider settings, and retry moved to Ctrl+R.
- **Slash menu**: pressing Enter on `/provider`, `/login` or `/openrouter` in the menu opens the matching panel directly, with no second press.
- **Titles and automatic approval**: generating a title on OpenRouter uses the lowest reasoning strength the model supports, and the title output ceiling went from 64 to 1024; the automatic-approval self-check now requests low strength and its output ceiling went from 768 to 4096.
- **Migration**: an OpenRouter configuration an older version wrote under `llm-pi-ai` is cleared automatically and the pi-ai route is no longer loaded; reasoning content in a session from the pi-ai era still passes back.

Exit DSCODE sessions using the same data directory before upgrading:

```sh
npm install -g @toddzheng024/dscode@0.7.7
dscode update 0.7.7
```

`dscode-0.7.7.tar.gz` can also be downloaded from GitHub Releases to install the standalone source package; the two installation forms use different data directories and never migrate sessions or credentials automatically.

Verification covers unit, the coverage baseline, eval, integration, TUI and package build. New here:
- Real OpenRouter key calls to DeepSeek V4 Flash, GLM 5.3 Flash, Kimi K2.6, Qwen 3.8 27B, Muse Spark 1.3 and Muse Spark 1.3 Contributor: tool calls, a continued turn with reasoning content passed back, a cache hit on a repeated prefix, the actual charge, and a title request; GLM reasoning pass-back was verified pinned to Z.AI; plus the error for an invalid model and OpenRouter web search.
- Real Ink rendering: the compaction animation at various widths, the model-switch confirmation, the `/openrouter` panel and management-key input, `/model` direct search and its focus rules, and the slash-menu Enter.
- Real account reads: an ordinary key reads the account balance; an ordinary key is refused by management-key validation.
- Offline login verification: in a real Host the OpenRouter route lists models from the cached model list with the correct bands, and the request body is intercepted before the network call.

Not done / known limits:
- The explicit cache breakpoints for Alibaba-hosted Qwen could not be measured (the account's zero-data-retention setting blocks those endpoints).
- All-key usage and 30-day spend under a management key were verified with simulated data only, with no real management key.
- Claude, GPT and Gemini are best-effort support, and Anthropic models no longer get automatic cache breakpoints the way pi-ai gave them.
- A cache hit depends on the upstream provider OpenRouter picks for the session.
