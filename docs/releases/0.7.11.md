# DSCODE 0.7.11

This release moves the built-in TUI from `dsh-code` 1.0.6 to **1.2.0** and ships several earlier changes with it.

- **TUI moved to dsh-code 1.2.0**: all 25 DSCODE patches were re-aligned. This upstream version changed a great deal — the local command catalogue moved to i18n `descriptionKey`, the `Header` component was rewritten, the input layer was restructured, and `/language` and `/review` became upstream features. Our approach: inject a fallback branch into upstream's `t()` for the catalogue (without changing upstream message tables, to avoid type conflicts when merging source later), and deliberately take over `/language` and `/review` as a whole.
- **DSH pinned to `0.1.5-rc.2`**: the dependency graph and the runtime-patch gate moved together, and all 9 runtime patches were re-verified against rc.2 (including the macOS stdin probe).
- **`dscode update` upgrades the whole installation in one step**: the npm/Hub path replaces the launcher itself with npm first and then upgrades the profile; the tar path downloads the release tarball, verifies its sha256, swaps the directory in place and migrates `.runtime`/`.env`/the local config; a source checkout refuses and asks for a git pull. There is also an in-TUI `/update`: a detached helper completes the upgrade after you exit.
- **Startup version check**: the TUI reads the npm registry once at startup (8-second timeout, silent on failure) and suggests `/update` when there is a newer version; `DSCODE_UPDATE_CHECK=off` disables it.
- **Update notices in seven languages** (en/zh-CN/zh-TW/ja/ko/es): the startup notice uses the TUI language runtime and `/update` follows the saved language.
- **`/model` lists only the current provider's models, sorted alphabetically by display name** (numbers in natural order, GLM 5.2 before 5.3); the search only filters rows, never reorders them.
- **Code review is more reliable**: the output budget went from 8k to 32k (reasoning tokens included), and an attempt that burns the budget without writing a report is retried with a doubled budget up to 64k; it starts at the lowest reasoning level the model supports; `DSCODE_REVIEW_MODEL=provider/model` and `DSCODE_REVIEW_EFFORT=<level>` are supported (aligned with Codex's `review_model`); a failure carries each attempt's budget and usage diagnostics.
- **Error display**: an unexpected stop the user did not cancel (a hook block, a restart interruption, blocked) now uses the error colour instead of a dim turn marker.
- **New tooling**: `npm run probe:tui [directory]` quantifies the blast radius of the TUI patches in 30 seconds before an upgrade (this migration was driven by it).

This release upgrades no external dependency other than DSH (`@anionex/dsh-computer-use`, `chrome-devtools-mcp` and `node-addon-system` are already at their latest versions).

Verification: `npm run check` passes (258 unit tests, 44 evaluation tests; lint, dependency integration, 4 real Ink UI verifications — TUI rendering/scrollback replay/effort bar/model search — and the package checks all pass). During the migration three classes of verification problem caused by upstream behaviour changes were found and fixed: `time-context` injection, the new `view.pending` field, and the new `recordHistory` prop.
