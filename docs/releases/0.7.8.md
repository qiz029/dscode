# DSCODE 0.7.8

This release fixes the experience of a long task reviewing repeatedly and expanding the work after its checks already passed, and tunes local session data handling.

- Automatic code review is capped at two rounds per user task, 90 seconds per round, 8,192 output tokens per model request, at low reasoning effort. Changing path, failing, or resuming a session does not hand back the full budget; the second round focuses on the issues already fixed and their direct regressions. An unfinished review is never reported as passing, and the user can still run `/review` by hand.
- The default agent rules ask for a statement before starting, an update on a key discovery, and, in a long task, ordinary prose progress roughly every minute. Non-verbose mode shows these too; a blocking tool can delay an update, and whether the model follows this still needs verification on real tasks.
- State the task scope and acceptance criteria, verify a review finding before acting on it, and run the affected checks after a fix. Once the checks pass, move to delivery instead of expanding into optional optimization again.
- Session metrics gained a bounded incremental read cache and a footer computation cache, and handle a final line without a newline correctly. Session cards reuse the content summary, and the memory job avoids large array spreads.
- The mailbox gained historical retention and per-recipient event cleanup while keeping undelivered messages; tests use their own small limits instead of writing 50,000 rows.
- OpenRouter empty SSE data is filtered and a corrupt cache re-read is throttled; plus build import-path validation, decoupling of the shared patch helpers, backoff for the macOS stdin probe and migration of older patches.

This release does not upgrade the upstream DSH dependencies.

Verification: `npm run check` passes (226 unit tests, 44 evaluation tests; 80.08% complete-source coverage; integration, the real Ink UI and the package checks pass). How a real model performs at progress communication and task convergence still needs validation in real use.
