# DSCODE 0.7.16

This release runs automatic compaction on the window messages can actually occupy, and adds a usable sandbox runner for restricted environments.

- **The compaction threshold is priced against the real message headroom (fix)**: the DeepSeek adapter counts the output budget (256k by default) inside the same 1M window, so a request whose "messages + output" exceeds the window is rejected outright; the threshold used to be priced against the whole window, which put the 90% line (943,718) **above** the real message ceiling (792,576), making a pressure compaction impossible to trigger first. Every compaction therefore came from overflow recovery: prune first, then write the summary synchronously on the spot — in the 0.7.15 log, `compaction/summary` appears **26.8 seconds** after `compaction/start`, and a prefetched compaction that only hangs off the pressure path never ran once. `effectiveContextWindow` now subtracts the output budget the adapter declares, so the threshold 713,318 and the prefetch start 634,061 both sit below the ceiling; the `/model` "switching will compact" preview uses the same window.
- **Overflow recovery skips the summary when the prune already fits (fix)**: overflow recovery pruned first and then summarised regardless. That 0.7.15 request exceeded the limit by only 125 tokens while the prune freed 87,018, so the summary was pure waste. After pruning it now re-checks with `fitsInWindow` (messages + output budget ≤ window): when it fits, it returns so the caller retries (the prune itself replaced the surface with `surfaceOp: replace`, so the retry condition holds), and only compacts when it does not; and a skip is allowed **only when a surface replacement really happened**, or the caller would not retry and the original error would be thrown at the user.
- **Sandbox runner (new, enabled by hand)**: `plugins/tui-tools/sandbox-runner.mjs` adds one `(allow file-write* (literal "/dev/ptmx"))` to the existing write policy — without it a confined command cannot allocate a PTY (`posix_openpt: Operation not permitted`), breaking a nested harness, tmux, expect and node-pty tests; inside an already confined process it **inherits** the outer profile instead of nesting another. Copy `config/harness.local.example.yml` to `config/harness.local.yml` to enable it, after which `npm run doctor`, `make release`, and "open another dscode inside a dscode session" all work.
- **The runner's notices are no longer mistaken for a failure (fix)**: the provider judges "non-zero exit + stderr matching `runnerFailureSignatures`" as a sandbox failure. The runner printed notices such as "inheriting the outer profile" with the same prefix, so inside a nested session any failing command was reported as a broken sandbox. A real failure now goes through `fatal:` and a notice through `notice:`, and the signatures in the example config match only the former.

Verification: `npm run check` passes (lint clean, all 315 unit tests green). The compaction fixes come with real contract tests — calling the DeepSeek adapter's `modelInfoFor` directly to confirm `defaultMaxTokens` is a top-level field and `effectiveContextWindow` yields 792,576 — plus engine-level regressions: the pressure path really triggers with an output budget; a prune that fits skips the summary while an unreplaced surface does not skip it; and the upgrade path is covered for pristine / v1-only / v2-only old engine states. The sandbox runner's apply path is covered by a shim that records the profile, and the inheritance path was measured on a real machine.
