# DSCODE 0.3.0

This release covers the login, terminal interaction and runtime improvements made after 0.2.0.

- `/login` saves a local DeepSeek key through a hidden input, loads it at startup and can reload it for the current session; an environment variable takes precedence.
- A horizontal effort bar with the Ultra animation, and a welcome box showing the version, model and project path.
- The composer is pinned to the bottom of the terminal and a long conversation uses an in-screen viewport; the full content stays viewable and exportable.
- A blank launch shows the composer first, and Chrome MCP connects when an agent session is created.
- Fixed `apply_patch` path handling inside a Git subdirectory.
- Hardened the startup and version-management locks and session message handling, and added the compaction evaluation tooling and an isolated test flow.

Upgrade:

```sh
npm install -g @toddzheng024/dscode@0.3.0
dscode update 0.3.0
```

Release verification covers local deterministic tests, TUI rendering, packaging and the Hub install lifecycle. A real remote model, a browser and desktop control are not part of this release's acceptance; the CJK candidate-window position still needs confirmation in the user's terminal.

Known display issue: the welcome box may still show `v0.2.0`, because the build reused the already-patched welcome component. The installed version is authoritative through `dscode --version` and `dscode doctor`; both the npm package and the Hub profile here are `0.3.0`.
